# BankProject

Учебное приложение для анализа банковской выгрузки в Excel. Оно преобразует операции в `pandas.DataFrame`, рассчитывает расходы, доходы и кешбэк, выполняет поиск по транзакциям и сохраняет результаты в JSON-отчёты.

Проект решает задачу автоматической подготовки банковской аналитики: вместо ручной фильтрации таблицы пользователь получает готовые данные для главной страницы, страницы событий и отдельных финансовых сервисов.

## Возможности

- загрузка операций из Excel и нормализация дат, пробелов и текстовых полей;
- анализ данных за неделю, месяц, год или весь доступный период;
- расчёт расходов и кешбэка по каждой карте, включая карты без расходов;
- выбор пяти крупнейших операций по абсолютной сумме;
- группировка расходов и доходов по категориям;
- выделение семи крупнейших категорий расходов и объединение остальных в категорию «Остальное»;
- отдельный расчёт переводов и снятия наличных;
- подбор категорий с наибольшим потенциальным кешбэком;
- расчёт суммы для «Инвесткопилки» при округлении операций до 10, 50 или 100 рублей;
- поиск операций по фрагменту описания без учёта регистра;
- поиск переводов по номеру телефона и имени получателя;
- получение курсов валют через APILayer и цен акций через Twelve Data;
- ежедневное кеширование данных внешних API;
- формирование отчётов по категории, дням недели, рабочим и выходным дням;
- логирование работы внешних API и сохранения отчётов.

## Бизнес-логика

Основная аналитика выполняется средствами pandas: логические маски отбирают операции, а `groupby`, `sum`, `reindex` и сортировка формируют итоговые показатели.

При расчётах учитываются следующие правила:

- расходом считается операция с отрицательной суммой, доходом — с положительной;
- операции со статусом `FAILED` не входят в расходы;
- для расчёта кешбэка и «Инвесткопилки» используются только операции со статусом `OK`;
- внутренние операции с упоминанием «Инвесткопилки» или брокерского счёта исключаются из аналитики событий;
- положительные операции категории «Маркетплейсы» не считаются доходом;
- неразрывные пробелы из Excel заменяются обычными, а крайние пробелы удаляются;
- суммы категорий в результатах округляются до целых рублей.

## Результаты работы

После запуска приложение создаёт следующие файлы:

| Файл | Содержимое |
|---|---|
| `data/main_page.json` | приветствие, карты, топ операций, валюты и акции |
| `data/events_page.json` | расходы, доходы, переводы, наличные, валюты и акции |
| `data/cashback_categories.json` | потенциальный кешбэк по категориям |
| `data/investment_bank.json` | возможное пополнение «Инвесткопилки» |
| `data/simple_finder.json` | результаты текстового поиска |
| `data/mobile_phone_finder.json` | операции с российскими номерами телефонов |
| `data/individual_transaction_finder.json` | переводы физическим лицам |
| `data/reports/*.json` | аналитические отчёты за последние три месяца |

Пример структуры данных страницы событий:

```json
{
  "expenses": {
    "total_amount": 125000,
    "main": [
      {"category": "Супермаркеты", "amount": 32000},
      {"category": "Остальное", "amount": 18000}
    ],
    "transfers_and_cash": []
  },
  "income": {
    "total_amount": 150000,
    "main": []
  },
  "currency_rates": [],
  "stock_prices": []
}
```

Суммы в примере приведены только для демонстрации формата.

## Архитектура

```text
BankProject/
├── data/
│   ├── cache/                 # ежедневный кеш внешних API
│   ├── reports/               # сформированные отчёты
│   ├── MyOperations.xlsx      # локальная банковская выгрузка
│   └── user_settings.json     # выбранные валюты и акции
├── logs/                      # журналы работы приложения
├── src/
│   ├── main.py                # сценарий запуска
│   ├── views.py               # данные главной страницы и событий
│   ├── services.py            # кешбэк, инвесткопилка и поиск
│   ├── reports.py             # аналитические отчёты
│   ├── decorators.py          # сохранение отчётов в JSON
│   ├── utils.py               # Excel, даты и нормализация данных
│   └── logger.py              # настройка логирования

```

Расчёты отделены от записи результата: функции представлений и сервисов работают с единым `DataFrame`, а JSON используется только на границе приложения. Доступ к валютам и акциям изолирован во внешних запросах с кешем на текущую дату, поэтому повторный запуск не расходует лимит API без необходимости.

## Установка

Требуются Python 3.14 и [Poetry](https://python-poetry.org/).

```bash
git clone <URL-репозитория>
cd BankProject
poetry install
```

Создайте локальный файл окружения из шаблона.

PowerShell:

```powershell
Copy-Item .env_example .env
```

Linux или macOS:

```bash
cp .env_example .env
```

Добавьте API-ключи в `.env`:

```env
CURRENCY_API="your API key"
STOCK_API="your API key"
```

- `CURRENCY_API` — ключ APILayer Exchange Rates Data;
- `STOCK_API` — ключ Twelve Data.

Без ключей основная аналитика продолжит работать, но списки валют и акций будут пустыми.

## Подготовка данных

Поместите банковскую выгрузку в `data/MyOperations.xlsx`. Ожидаются столбцы:

- `Дата операции`;
- `Дата платежа`;
- `Номер карты`;
- `Статус`;
- `Сумма операции`;
- `Валюта операции`;
- `Категория`;
- `Описание`.

Файл содержит финансовые данные и исключён из Git. Не публикуйте реальные операции и API-ключи.

### Настройка отслеживаемых валют и акций

Список интересующих валют и акций настраивается в файле `data/user_settings.json`. Укажите в нём коды валют и биржевые тикеры, которые должны отображаться в отчётах приложения:

```json
{
  "user_currencies": ["USD", "EUR"],
  "user_stocks": ["AAPL", "AMZN", "GOOGL"]
}
```

- `user_currencies` — коды нужных валют, например `USD`, `EUR` или `CNY`;
- `user_stocks` — тикеры интересующих акций, например `AAPL`, `AMZN` или `GOOGL`.

После изменения файла следующий запуск сформирует страницы с курсами и ценами только для выбранных инструментов. Для загрузки актуальных данных должны быть заполнены соответствующие API-ключи в `.env`.

## Запуск

По умолчанию приложение анализирует операции на текущую дату, формирует страницы за месяц, рассчитывает округление до 100 рублей и ищет строку «Оплата»:

```bash
poetry run python src/main.py
```

Параметры сценария задаются в блоке `if __name__ == "__main__"` файла `src/main.py`:

```python
data = data_with_normalized_spacebars()

pages(date=datetime.today(), transactions=data, range_type="M")
services(date=datetime.today(), transactions=data, limit=100, search_string="Оплата")
reports(transactions=data, category="Переводы")
```

Допустимые значения `range_type`:

| Значение | Период |
|---|---|
| `W` | с понедельника выбранной недели |
| `M` | с первого дня выбранного месяца |
| `Y` | с первого января выбранного года |
| `ALL` | все операции с 1 января 1900 года |

Допустимые значения `limit`: `10`, `50` или `100`.

## Тестирование

```bash
poetry run pytest
poetry run pytest --cov=src
```

Тесты находятся в `tests/` и проверяют утилиты, представления, сервисы, отчёты и декоратор сохранения результатов. Внешние API и файловые операции подменяются тестовыми объектами, чтобы проверки не зависели от сети и личных данных.

## Проверка качества кода

```bash
poetry run black --check src tests
poetry run isort --check-only src tests
poetry run flake8 src tests
poetry run mypy src
```

Для автоматического форматирования уберите `--check` у Black и замените `--check-only` на обычный запуск isort.

## Git и безопасность

`.gitignore` исключает `.env`, IDE-настройки, кеши Python, отчёты покрытия, логи, банковскую выгрузку и сгенерированные JSON-файлы. В репозитории остаются исходный код, тесты, `poetry.lock`, шаблон окружения и безопасные пользовательские настройки.

История проекта ведётся небольшими тематическими коммитами в формате Conventional Commits:

```text
feat: add transaction reports
fix: exclude failed operations from expenses
refactor: migrate transaction processing from dictionaries to DataFrame
test: update service tests
docs: improve project README
```

## Формат проекта

BankProject — локальное консольное приложение: отдельный сервер или база данных для запуска не нужны. Результаты сохраняются рядом с проектом и предназначены для последующего отображения интерфейсом или анализа как JSON.
